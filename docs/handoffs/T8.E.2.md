## 关键设计决策

1. **D5 缺省值**：``LOWER-MULTIPLICITY`` 缺省 ``0``；``UPPER-MULTIPLICITY`` 缺省 ``1``；
   ``"unbounded"`` → ``-1``。
2. **D8 内存控**（T8.E.2 妥协）：本任务用 ``etree.parse`` 而非 ``iterparse`` 解析
   module body（每个 module 体内深度有限，200K 行 BSWMD 也是 OK 的；iterparse 优化
   留给后续 Sprint 9.x 在真实 BSWMD 上 profile 后再决定）。
3. **namespace prefix 不敏感**：所有元素访问用 ``etree.QName(tag).localname`` 匹配；
   ``arx:ECUC-MODULE-DEF`` 和 ``ECUC-MODULE-DEF`` 等价（已写 ``arx:`` 测试覆盖）。
4. **multi-package 支持**：扫所有 ``<AR-PACKAGE>`` 兄弟节点（不只根包）→ vendor 三方
   BSWMD（``/Vendor/NXP/``）能与标准 BSWMD（``/AUTOSAR/``）共存。
5. **path walk 容错**：
   - 首段 ``/AUTOSAR/`` 或 ``/Vendor/`` 等根包名自动跳掉（按 ``root_package_name``
     探测值）
   - 末段允许命中 ParamDef（不是只有 ContainerDef）→ ``lookup_param`` 准确
   - miss 全部返回 ``None``（不抛 — 契约 2 向后兼容）
6. **ecuc.py BSWMD 优先**：传 ``bswmd_registry`` 时先调
   ``bswmd_registry.lookup_param(def_ref.text)`` 严格推断；miss 时 fallback DEST 启发
   式。未传 ``bswmd_registry`` 时完全走 Sprint 3 行为（不破 7 个老 test）。

## 实施细节

### bswmd.py 解析流程

```
load(paths)
  → etree.parse(path)
  → 探测 root <AR-PACKAGE> SHORT-NAME（默认 "AUTOSAR"）
  → 扫所有 <AR-PACKAGE> 兄弟节点（不是只根包）
    → 扫每个 <ELEMENTS> 下的 <ECUC-MODULE-DEF>
      → _parse_module_def: 解析 <CONTAINERS> + 顶层 <PARAMETERS>
        → _parse_container_def: 递归 <PARAMETERS> + <SUB-CONTAINERS>
        → _parse_param_def: 解析类型 / min / max / default / multiplicity / symbols
```

### _parse_param_def 关键点

- 元素 localname → ``ParamType`` 映射（``_PARAM_TYPE_FROM_LOCAL`` 字典）
- 未知 ``*-PARAM-DEF`` → 跳过（不抛，向后兼容）
- ``<MIN>`` / ``<MAX>``：字面量直接保留为 ``str``（不在解析层做 int / float 转换 —
  type/range 校验留给 ``bsw_write_path.py`` T8.E.3）
- ``<DEFAULT-VALUE>``：可能包 ``<ECUC-NUMERICAL-PARAM-VALUE>`` 内，也可能直接 text
  → 两种情况都支持
- ``<UPPER-MULTIPLICITY>unbounded</...>`` → ``-1``
- ENUMERATION：扫 ``<LITERALS> → <ECUC-ENUMERATION-LITERAL-DEF> → <SHORT-NAME>``
  收集为 ``symbol_strings: tuple[str, ...]``

## 已知问题 / TODO（不在本任务范围）

1. **iterparse 优化（D8）**：T8.E.2 用了 ``etree.parse`` 一次性解析；真实 200K 行
   BSWMD profile 后若发现内存峰值超过 100MB，切换到 ``iterparse`` + ``clear(keep_tail=True)``。
   本任务不 profile 真实文件（避免引入 out-of-scope benchmark）。
2. **CHOICE-CONTAINER-DEF 浅解析**：本任务把 ``ECUC-CHOICE-CONTAINER-DEF`` 解析为
   ``ContainerDef``（与 ``ECUC-PARAM-CONF-CONTAINER-DEF`` 同形），但 **未**展开 CHOICE
   内的多个 choice 候选项。BSWMD spec 允许 CHOICE 容器有多个 alternative child，真实
   BSWMD 偶尔有但不是主流。留给 Sprint 9.x 扩展。
3. **reference 解析（ECUC-REFERENCE-DEF）**：本任务**不**解析 ``<ECUC-REFERENCE-DEF>``
   元素（不在 ``_PARAM_TYPE_FROM_LOCAL`` 中）。Reference param 在 ``ecuc.py`` 走
   ``ECUC-REFERENCE-VALUE`` 的 raw 路径处理，不依赖 BSWMD 类型。T8.E.3 校验 reference
   写值时如需 BSWMD，可扩展。
4. **FUNCTION-NAME-DEF**：本任务支持，但 ``_map_param_type_to_ecuc`` 返回 None
   （不在 ECUCType 5 种内）→ fallback DEST 启发式。FUNCTION-NAME 在 EB tresos 工程
   里罕见，不影响主线功能。
