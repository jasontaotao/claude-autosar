2安装 Python 包

v0.3.0 已发布到 PyPI，全世界 pip install 即可。三种路径二选一： 开发期用 editable 装（你改 packages/autoc/src/claude_autosar/ 立即生效）；生产用 PyPI；内网用本地 wheel/sdist。

从 PyPI 装

claude-autosar --version

路径 B · 开发

从 monorepo editable 装

需要：仓库 clone 在 D:/claude_proj2/autoc-cc。装含 dev 依赖（pytest / ruff / mypy / black / isort / bandit / pre-commit）。

cd D:/claude_proj2/autoc-cc
pip install -e packages/autoc[dev]
claude-autosar --version
# → claude-autosar 0.3.0

路径 C · 本地 wheel / sdist 离线装（生产 / 内网）

cd D:/claude_proj2/autoc-cc
rm dist/*
cd packages/autoc

# → dist/claude_autosar-0.3.0-py3-none-any.whl  (200 KB)
# → dist/claude_autosar-0.3.0.tar.gz           (151 KB)

pip install --force-reinstall dist/claude_autosar-0.3.0-py3-none-any.whl
claude-autosar --version   # → claude-autosar 0.3.0

仓库根 dist/ 现有产物是旧版（文件名 autoc-0.1.0-*，66KB + 51KB），未上传 PyPI。 PyPI 上的新版是 claude_autosar-0.3.0-*（200KB + 151KB）。 若要在本地拿到同名 wheel，按上面路径 C 重 build 即可。

同样两种方式。开发期用 local plugin dir 直接挂路径（最快、所见即所得）；长期用走 marketplace + install。

在 Claude Code 对话里执行：

5第一次使用

cd 到你的 EB tresos / DaVinci / ARXML 工程根，新开 Claude Code 会话。SessionStart hook 会自动识别工程类型、注入上下文。

5.1 子 Agent 入口（最常用）

> /claude-autosar:bsw-config --module Mcu --param \
    Mcu/Clock0/ClockFreq=80000000 --param Mcu/Clock0/ClockSrc=1

这是 bsw-config 子 Agent，会自动：

  1. 检测工程类型（.project → EB tresos / *.dpa → DaVinci / *.arxml → 纯 ARXML）
  2. 读 Mcu 模块当前 BSWMD 列表 + 当前值（bsw_read）
  3. 确认改参范围合法（--module 存在、--param 路径在 BSWMD 内）
  4. 写新值到 .prefs/Mcu.xdm（bsw_write，adapter 调 tresos_cmd，失败自动回滚）
  5. 跑 verify 确认无 schema 错（bsw_verify，Sprint 9.3 起结构化解析 6 类正则）
  6. 如带 --autocalc → 触发衍生参数重算
  7. 写 session：~/.claude-autosar/agent/sessions/<id>.jsonl

5.2 直接调斜杠命令（不带 Agent）

# 改 EB tresos 工程 + 自动 write session
> /claude-autosar:eb-save --module Mcu --param Mcu/Clock0/ClockFreq=80000000 --verify

# 改 DaVinci 工程（不写 autocalc，DaVinci Protocol 不含）
> /claude-autosar:davinci-verify --module EcuC --param EcuC/EcuCConfiguration/OsApp=OSApp1 --save

# 校验一份 arxml / xdm 文件
> /claude-autosar:arxml-validate --file Bswmd/Mcu_Bswmd.arxml

# 看改参历史（按时间倒序）
> /claude-autosar:log --view timeline

# 按 (module, path) 分组看
> /claude-autosar:log --view by-url

# 看 session 树（fork + parent）
> /claude-autosar:session-tree show latest

# 导出自包含 HTML（带绿/黄/红 callout）
> /claude-autosar:export --output report.html

5.3 M1-T 模板 diff + apply（Sprint 9.2 新增）

把当前工程配置和厂商模板对比，dry-run 看 diff，确认后回写：

# 仅看 diff，不写
> claude-autosar arxml-apply-template --base Bswmd/Mcu_Bswmd.arxml \
    --template vendor_templates/Mcu_R24-11.arxml --dry-run

# 真改
> claude-autosar arxml-apply-template --base Bswmd/Mcu_Bswmd.arxml \
    --template vendor_templates/Mcu_R24-11.arxml --apply

# 同上，XDM 端
> claude-autosar xdm-apply-template --base .prefs/Mcu.xdm \
    --template vendor_templates/Mcu_template.xdm --apply --output diff.html

5.4 M4 lint 10 规则（Sprint 9.4 新增）

扫单个 .arxml / .xdm 文件，跑 10 条规则（8 arxml + 2 xdm），按 namespace 自动过滤：

> claude-autosar lint Bswmd/Can_Can.arxml
# → {"success": true, "violations": [...], "lint_summary": {...}}

# 只看 ERROR 级 + 导 HTML 报告
> claude-autosar lint Bswmd/Can_Can.arxml --severity error --output report.html

5.5 没装 EB tresos 也能玩

没装商业工具时，claude-autosar 走 stub adapter：

> /claude-autosar:eb-save --module Mcu --param Mcu/Clock0/ClockFreq=80000000 --adapter stub

stub 把所有 subprocess 调用替换成"读 .prefs/<Module>.xdm → 改文本 → 写回 → 假 verify pass"，跑通整个数据流，CI 测试就是用这个模式。

关键设计：

  • MCU 差异化解耦 — TresosAdapter.discover() 数据驱动；同一段代码处理 S32K3 / TC3xx / RH850，无 if/else 分支
  • 双格式平级 IO — .arxml 和 .xdm 各自独立 dataclass / extractor / templates，不互转（plan v2 §2.1 锁定）；dispatcher 按文件 suffix 路由
  • 不可变数据 — 所有公开 dataclass frozen=True；with_X() / set_value() 返回新实例
  • JSONL append-only — session 存储；os.fsync Windows 强持久
  • trust boundary — MCP 工具的 project / tresos_home 入参白名单（ISO 21434）
  • lint 异常隔离 — LintRunner try 提到 for v in yielded: 包含 __next__()，单条 rule 抛错不影响其它 rule

11故障排查

Q1. claude-autosar 命令找不到

$ claude-autosar --version
'claude-autosar' 不是内部或外部命令

解：重开 shell，或显式 python -m claude_autosar.cli.main --version。Windows 下确认 %LOCALAPPDATA%\Programs\Python\Python3X\Scripts\ 在 PATH。

Q2. /plugin install claude-autosar 报 hooks.json 错

Failed to load hooks from .../hooks/hooks.json:
  expected record, received undefined, path: ["hooks"]

解：检查文件顶层有 "hooks": {...} 包装：

$ cat packages/plugin/plugins/claude-autosar/hooks/hooks.json
{
  "hooks": {
    "PreToolUse": [ ... ],
    "PostToolUse": [ ... ],
    "SessionStart": [ ... ]
  }
}

Q3. MCP server 启动失败

[ERROR] Failed to start MCP server 'claude-autosar': No module named 'claude_autosar.cli.mcp_server'

解：

  1. pip install -e packages/autoc[dev]（确保 claude-autosar 已装）
  2. 检查 packages/plugin/plugins/claude-autosar/.mcp.json 的 env.PYTHONPATH 指向 packages/autoc/src
  3. 单独跑 python -m claude_autosar.cli.mcp_server 应能启动 stdio server

Q4. ARXML guard 误拒合法文件

ARXML guard: ARXML schema invalid: ...

可能原因：ARXML 用了不常见 namespace prefix（guard 期望 ar:）/ 包含 <?xml-stylesheet ?> 处理指令 / lxml 解析严于浏览器。

解：两种真绕过方式（不要听信"改用 Edit"误导）：

  1. 临时把要写的文件改个名（不在 *.arxml 匹配里）
  2. 用 MultiEdit（guard matcher 是 Write|Edit，不含 MultiEdit）

改完再 mv 回来 — 不会触发 guard。

Q5. /claude-autosar:eb-save 改参后 verify 报失败

ValidatorError: verify 失败，已回滚到 snapshot

解：claude-autosar 失败自动回滚（pre-改前 snapshot 在 %TEMP%）。常见原因：

  • 参数值超出 BSWMD 范围（如 McuClockReferencePointFrequency=999999999999）
  • 依赖参数没一起改（autocalc 衍生）— 用 /claude-autosar:bsw-config 子 Agent 入口，它会自动跑 autocalc
  • .prefs/<Module>.xdm 本身已损坏 — 先用 /claude-autosar:eb-save --module <Module> --adapter stub 验证 stub 走得通；stub 过 + real 挂 = real 工程问题

Q6. session_show("latest") 拿到旧的 session

已修（Sprint 5 H1）：从字母序改成 mtime 序。如果你拿到的仍是字母序，说明 pip install -e 没生效：

$ python -c "from claude_autosar.core.session.store import resolve_latest_session_id; print(resolve_latest_session_id.__module__)"
# 应输出 claude_autosar.core.session.store，不是 claude_autosar.core.session.store (cached)

删 __pycache__/ + .pytest_cache/ 再试。

Q7. claude-autosar lint 在 .xdm 上抛 AttributeError

已修（Sprint 9.5 集成修复）。如果你用的旧 wheel 仍报，原因是 8 条 arxml 规则用 key_params 字段，被喂 XDM 数据时抛 AttributeError。修法：

  1. 每条规则加 applies_to: ClassVar[str] tag（"arxml" / "xdm" / "both"）

Q8. M1-T arxml-apply-template --apply 后字节变了但内容没改

已修（Sprint 9.2 + 9.4）。原 datamodel2_io.write 的 XDM d:var 段在改值无变化时静默返回原字节，丢失改参。修法：c14n compare 区分"真无变化 vs d:var 变化"；any_changed=False 返 None 让 caller 试 parent-form 重建。
