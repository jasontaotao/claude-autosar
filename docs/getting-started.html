TL;DR

# 1. 装 autoc Python 包
pip install -e "D:/claude_proj2/autoc-cc/packages/autoc[dev]"

# 2. 装好后启动 Claude Code，挂 autoc 插件（开发模式）
cd D:/claude_proj2/autoc-cc
claude --plugin-dir ./packages/plugin/plugins/autoc --debug

# 3. 在 Claude Code 对话里跑一条命令验证
> /autoc:bsw-config --module Mcu --param Mcu/ClockConfiguration/...=80000000

1系统要求

依赖最低版本说明
Python3.11+需要 dict | None、tomllib、match-case
Claude Code最新插件支持 0.2.0+
EB tresos24.x / 26.x仅在改 EB 工程时需要；没装也能用 stub adapter
DaVinci Configurator5.x仅在改 DaVinci 工程时需要
lxml4.9+ARXML 读写 + guard hook 用，autoc 依赖里已含
OSWin / Linux / macOSCI 跑 3.11 + 3.12；本地装上 3.13 也行

2安装 autoc Python 包

两种路径二选一。开发期用 editable 装（你改 packages/autoc/src 立即生效）；PyPI 0.1.0 发布后用 pip install autoc。

路径 A · 开发

从 monorepo editable 装

需要：仓库 clone 在 D:/claude_proj2/autoc-cc。

cd D:/claude_proj2/autoc-cc
pip install -e "packages/autoc[dev]"
路径 B · 生产

从 PyPI 装（等 0.1.0 发布后）

需要：先完成 PyPI trusted publisher 配置（见 §10 排错 末尾） + 触发 release.yml 跑通。

pip install autoc

装好自检：

$ autoc --version
autoc 0.1.0
$ autoc --help
usage: autoc [-h] [--version] [--project PROJECT] [--verbose] [--no-color]
             {eb,davinci,session,log,export} ...
i

Windows 下 autoc CLI 不在 PATH？
用 python -m autoc.cli.main 显式跑；或重开 shell 让 pip install 写入的 Scripts 目录生效。

3加载插件到 Claude Code

同样两种方式。开发期用 local plugin dir 直接挂路径（最快、所见即所得）；长期用走 marketplace + install。

方式 A · local plugin dir（推荐开发）

cd D:/claude_proj2/autoc-cc
claude --plugin-dir ./packages/plugin/plugins/autoc --debug

启动后直接能用 /autoc:* 命令。改 packages/plugin/plugins/autoc/ 下任何文件，Ctrl+R 重载即可。

方式 B · marketplace + install（生产用法）

在 Claude Code 对话里执行：

> /plugin marketplace add D:/claude_proj2/autoc-cc/packages/plugin
> /plugin install autoc
> /plugin validate autoc
> /plugin list

应看到：

installed plugins:
  - autoc (0.1.0)  ✓ valid
!

路径用正斜杠 D:/...，不要用 D:\d\... 这种盘符切换前缀 — Claude Code 不解释 shell 风格盘符。

!

如果报 Failed to load hooks: expected record, received undefined, path:["hooks"]，
说明 hooks.json 顶层缺 "hooks": {...} 包装。autoc-cc 0.1.0 仓库里这是 0309498 已修的 bug；如遇自检 cat packages/plugin/plugins/autoc/hooks/hooks.json | head -1 应该是 { "hooks": { 开头。

5第一次使用

cd 到你的 EB tresos 工程根（有 .project 文件），新开 Claude Code 会话。SessionStart hook 会自动识别工程类型、注入 4 段上下文。

5.1 子 Agent 入口（最常用）

> /autoc:bsw-config --module Mcu --param \
    Mcu/ClockConfiguration/McuClockSettingConfig_0/McuClockReferencePointFrequency=80000000

这是 bsw-config 子 Agent，会自动：

  1. 读 Mcu 模块当前 BSWMD 列表 + 当前值（bsw_read）
  2. 确认改参范围合法（--module 存在、--param 路径在 BSWMD 内）
  3. 写新值到 .prefs/Mcu.xdm（bsw_write，adapter 调 tresos_cmd）
  4. 跑 verify 确认无 schema 错（bsw_verify）
  5. 写 session：~/.autoc/agent/sessions/<id>.jsonl

5.2 直接调子命令（不带 Agent）

# 改 EB tresos 工程 + 自动 write session
> /autoc:eb-save --module Mcu --param Mcu/.../Freq=80000000

# 改 DaVinci 工程（不写 autocalc，DaVinci Protocol 不含）
> /autoc:davinci-verify --module EcuC --param EcuC/.../OsApp=OSApp1

# 校验一份 arxml 文件
> /autoc:arxml-validate --file Bswmd/Mcu_Bswmd.arxml

# 看改参历史（按时间倒序）
> /autoc:log --view timeline

# 按 (module, path) 分组看
> /autoc:log --view by-url

# 看 session 树（fork + parent）
> /autoc:session-tree

# 导出自包含 HTML（带绿/黄/红 callout）
> /autoc:export --output report.html

5.3 没装 EB tresos 也能玩

没装商业工具时，autoc 走 stub adapter：

> /autoc:eb-save --module Mcu --param Mcu/...=80000000 --adapter stub

stub 把所有 subprocess 调用替换成"读 .prefs/<Module>.xdm → 改文本 → 写回 → 假 verify pass"，跑通整个数据流，CI 测试就是用这个模式。

6/autoc:* 斜杠命令完整清单

斜杠命令触发方式委派到的 MCP 工具用途
/autoc:bsw-config子 Agent 入口全部 bsw_* 工具交互式改参（最常用入口）
/autoc:eb-save直接bsw_read / bsw_write（EB adapter）EB tresos 改参 + verify + 写 session
/autoc:davinci-verify直接bsw_read / bsw_write（DaVinci adapter）DaVinci 改参 + verify（无 autocalc）
/autoc:arxml-validate直接arxml_validate校验 .arxml / .xdm 文件 schema
/autoc:session-tree直接session_list / session_show看改参 session 的 fork 树
/autoc:export直接session_exportsession 导出自包含 HTML
/autoc:log直接log_export按 timeline / by-url 渲染改参日志

7MCP 工具完整清单

10 个 FastMCP 工具，Claude Code 子 Agent 可直接调。错误统一 {"success": false, "error": "...", "field": "...", "param_index": N}。

工具签名说明
bsw_read(project, module, path?)读 BSWMD 当前值；5 种类型派生：int / float / bool / string / enum
bsw_write(project, module, params[], adapter?)改参 + 改后 verify + rollback on fail
bsw_verify(project, module)单独跑 verify，不改值
bsw_autocalc(project, module)autosar calc 派生参数（仅 EB adapter 支持）
arxml_validate(file_path)ARXML schema 校验
dbc_parse(file_path)DBC 解析 + CanIf 信号一致性
session_list(project?, limit?)列 session ID + mtime + 改参条数
session_show(session_id)单 session 详情（接受 "latest"）
session_export(session_id, output_path?)自包含 HTML 导出
log_export(project, view, session_id?)view ∈ {"timeline","by-url"}
★

所有 bsw_* 工具的 project 参数必须落在 _ALLOWED_PROJECT_ROOTS（当前 cwd）之内，tresos_home 必须在 project 之内 — ISO 21434 信任边界。这是为了防 LLM 误传路径读到工程外文件。

8架构

┌────────────────────────────────────────────────────────────┐ │ Claude Code (LLM) │ │ ├─ /autoc:* 斜杠命令 ───→ commands/*.md │ │ ├─ bsw-config 子 Agent ─→ agents/bsw-config.md │ │ └─ 知识注入（自动） ──→ skills/*/SKILL.md │ └────────────────────────────┬───────────────────────────────┘ │ MCP (stdio, JSON-RPC) ▼ ┌────────────────────────────────────────────────────────────┐ │ autoc.cli.mcp_server (FastMCP, 10 tools) │ │ ├─ bsw_read / bsw_write / bsw_verify / bsw_autocalc │ │ ├─ arxml_validate / dbc_parse │ │ └─ session_list / session_show / session_export / log_export│ └────────────────────────────┬───────────────────────────────┘ │ ┌────────────────────┼────────────────────┐ ▼ ▼ ▼ ┌──────────────┐ ┌──────────────┐ ┌──────────────────┐ │ core.bsw │ │ core.session │ │ adapters/ │ │ - arxml_io │ │ - store │ │ - tresos.py │ │ - ecuc │ │ - tree │ │ - davinci.py │ │ - validator │ │ - recorder │ │ - stub.py │ │ - config │ │ - exporter │ │ (Protocol) │ └──────────────┘ └──────────────┘ └──────────────────┘ │ │ ▼ ▼ ┌──────────────┐ ┌──────────────────┐ │ ~/.autoc/ │ │ subprocess: │ │ agent/ │ │ tresos_cmd.bat │ │ sessions/ │ │ DVCfgCmd.exe │ │ .current │ │ (Windows .bat │ └──────────────┘ │ 走 cmd /c) │ └──────────────────┘

关键设计：

  • MCU 差异化解耦 — TresosAdapter.discover() 数据驱动；同一段代码处理 S32K3 / TC3xx / RH850，无 if/else 分支
  • 不可变数据 — 所有公开 dataclass frozen=True；with_X() / set_value() 返回新实例
  • JSONL append-only — session 存储；os.fsync Windows 强持久
  • trust boundary — MCP 工具的 project / tresos_home 入参白名单

9故障排查

Q1. autoc 命令找不到

$ autoc --version
'autoc' 不是内部或外部命令

解：重开 shell，或显式 python -m autoc.cli.main --version。Windows 下确认 %LOCALAPPDATA%\Programs\Python\Python3X\Scripts\ 在 PATH。

Q2. /plugin install autoc 报 hooks.json 错

Failed to load hooks from .../hooks/hooks.json:
  expected record, received undefined, path: ["hooks"]

解：检查文件顶层有 "hooks": {...} 包装：

$ cat packages/plugin/plugins/autoc/hooks/hooks.json
{
  "hooks": {
    "PreToolUse": [ ... ],
    "PostToolUse": [ ... ],
    "SessionStart": [ ... ]
  }
}

Q3. MCP server 启动失败

[ERROR] Failed to start MCP server 'autoc': No module named 'autoc.cli.mcp_server'

解：

  1. pip install -e packages/autoc[dev]（确保 autoc 已装）
  2. 检查 packages/plugin/plugins/autoc/.mcp.json 的 env.PYTHONPATH 指向 packages/autoc/src
  3. 单独跑 python -m autoc.cli.mcp_server 应能启动 stdio server

Q4. ARXML guard 误拒合法文件

ARXML guard: ARXML schema invalid: ...

可能原因：ARXML 用了不常见 namespace prefix（guard 期望 ar:）/ 包含 <?xml-stylesheet ?> 处理指令 / lxml 解析严于浏览器。

解：两种真绕过方式（不要听信"改用 Edit"误导）：

  1. 临时把要写的文件改个名（不在 *.arxml 匹配里）
  2. 用 MultiEdit（guard matcher 是 Write|Edit，不含 MultiEdit）

改完再 mv 回来 — 不会触发 guard。

Q5. /autoc:eb-save 改参后 verify 报失败

ValidatorError: verify 失败，已回滚到 snapshot

解：autoc 失败自动回滚（pre-改前 snapshot 在 %TEMP%）。常见原因：

  • 参数值超出 BSWMD 范围（如 McuClockReferencePointFrequency=999999999999）
  • 依赖参数没一起改（autocalc 衍生）— 用 /autoc:bsw-config 子 Agent 入口，它会自动跑 autocalc
  • .prefs/<Module>.xdm 本身已损坏 — 先用 /autoc:eb-save --module <Module> --adapter stub 验证 stub 走得通；stub 过 + real 挂 = real 工程问题

Q6. session_show("latest") 拿到旧的 session

已修（Sprint 5 H1）：从字母序改成 mtime 序。如果你拿到的仍是字母序，说明 pip install -e 没生效：

$ python -c "from autoc.core.session.store import resolve_latest_session_id; print(resolve_latest_session_id.__module__)"
# 应输出 autoc.core.session.store，不是 autoc.core.session.store (cached)

删 __pycache__/ + .pytest_cache/ 再试。

Q7. PyPI trusted publishing 配错

PyPI 项目首次发布要求 owner 去 PyPI dashboard 做一次性配：

  1. 登录 https://pypi.org → 项目 autoc → Settings → Publishing → Add a new pending publisher
  2. 填 4 字段：Owner=autoc-cc、Repository=autoc-cc、Workflow filename=release.yml、Environment name=pypi
  3. （推荐）GitHub repo → Settings → Environments → pypi → Required reviewers = 自己
  4. 触发：git tag v0.1.0 && git push origin v0.1.0

想先去 TestPyPI 试一遍：相同步骤在 https://test.pypi.org 配一遍，Environment name 填 test-pypi，然后 Actions → Release → Run workflow → 勾 "Upload to TestPyPI"。

10卸载

# 1. 移除 marketplace + 插件
> /plugin marketplace remove autoc-marketplace
> /plugin uninstall autoc

# 2. 卸载 Python 包
pip uninstall autoc

# 3. 删用户数据（可选）
rm -rf ~/.autoc/agent/sessions/     # 所有改参 session
rm -rf ~/.autoc/agent/.current      # "current" session 标记
